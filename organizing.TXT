HTTP 구조. 
0. HTTP(하이퍼 트랜스퍼 프로토콜) : 인터넷상에서 데이터를 주고 받기 위한 서버 / 클라이언트 모델을 따르는 프로토콜. 
1. HTTP(무상태) 프로토콜은 일반적으로 TCP/IP통신 위에서 동작. 
2. HTTP는 데이터를 '주고' -> '받는다'  (먼저 데이터를 받지 않는다. 서버가 먼저 데이터 전송X[단방향]) / 추후 배울 소켓은 양방향 전송.

http는 서블릿을 통해 java로 웹 구현이 가능하며,  서블릿은 아파치 톰켓을 통해서 브라우저로 연동이 가능해진다. 
(Spring Boot Web 에서는 내장되어있다. ) 

IP -> 네트워크에서 장치를 구별하는 고유 주소
PORT -> 네트워크를 사용하는 프로그램 식별번호

CMD.
IPCONFIG : 현재 내 PC의 와이파이 주소를 알 수 있음
NETSTAT -ANO : 현재 pc에 포트번호 전체 출력

HTTP Method Properties 
1. 안전 safe Method : 호출해도 리소스가 변경되지 않는다는 의미 
2. *멱등성* Idemportent : 한 번을 호출하든 여러번 호출하든 그 결과가 같음. 
3. 캐시 가능 Cacheable : 응답 결과 리소스를 캐시에서 사용할 수 있는가에 대한 여부

HTTP에서 질문 3개 , WAS에서 질문 3개를 할 거임. 


WAS는 정적 페이지와 동적 페이지로 나뉜다. 
1. 정적페이지 :  Web Server는 파일 경로 이름을 받아 경로와 일치하는 file Contents를 반환.  * 항상 동일한 페이지를 반환한다. * (image, html, css, javascript)
2. 동적페이지 : 인자의 내용에 맞게 동적인 Contents를 반환한다. 즉 , 웹 서버에 의해서 실행되는 프로그램을 통해 만들어진 결과물이다. 

WAS : 클라이언트의 요청을 처리하고 , 그 결과를 반환하는 Servlet 클래스의 구현 규칙을 지킨 자바 웹 프로그래밍 기술. 

1. 특징
*java* 기반의 웹 컴포넌트로써 java확장자를 가진다 .
서블릿은 웹 컨테이너에 의해 관리되며, 스레드로 동작되어 효율적인 요청처리가 가능하다. 
MVC패턴의 Controller 역할로 서블릿이 사용됨. 

2. 서블릿 컨테이너
컨테이너는 웹 컴포넌트를 저장하는 저장소 역할, 메모리 로딩, 객체 생성 및 초기화 등 서블릿의 생명주기를 관리하고, JSP를 서블릿으로 변환하는 기능을 수행하는 프로그램이다.


와이파이나 랜선은 데이터를 전달하는 물리/데이터링크 계층의 전송 매체이며, 
아파치 톰캣(Apache Tomcat)은 이를 받는 Application 계층의 Web Application Server(WAS)입니다.
localhost(127.0.0.1)를 통한 통신은 내부 루프백(Loopback) 네트워크 인터페이스를 거쳐 톰캣 서블릿 컨테이너의 8080 포트로 연결됩니다.

3. Web Server
기능. 
1. HTTP 프로토콜을 기반으로 하여 클라이언트의 요청을 서비스하는 기능을 담당한다.
2. 정적인 컨텐츠 제공, WAS를 거치지 않고 바로 자원을 제공한다.
3. 동적인 컨텐츠 제공을 위한 요청 전달
4. 클라이언트의 요청을 WAS에 보내고 , WAS가 처리한 결과를 클라이언트에게 전달한다. 
5. 클라이언트는 일반적으로 웹 브라우저를 의미한다 . 

4. Web Server Architecture

5. Servlet Life Cycle 
[클라이언트 요청] 
       │
       ▼
1. 객체 생성 및 메모리 로딩 (없을 경우에만 최초 1회)
       │
       ▼
2. init() 호출 ─────────► [초기화 : 최초 1회만 실행 (싱글톤)]
       │
       ▼
3. service() 호출 ──────► [요청 처리 : 클라이언트 요청마다 스레드 생성 후 실행]
       │                  └─► 요청 방식에 따라 doGet() / doPost() 호출
       ▼
4. destroy() 호출 ──────► [자원 해제 : 서버 종료 또는 서블릿 수정 시 1회 실행]

2. 서블릿은 어디서 제공해요? --> 아파치 톰켓(라이브러리)에서 제공하며, 스프링 부트에는 내장되어 있다 . 
3. 동작구조 --> 클라이언트 요청 -> 동적 컨텐츠는 바로 리스폰 
서블릿 컨테이너는? 웹 컴포넌트를 저장하는 저장소 역할  / jsp를 서블릿으로 변환하는 기능을 수행하는 프로그램
웹 컨테이너는 서블릿에 의해서 관리되며, 스레드로 동작한다. 


1. 클라이언트 요청 (HTTP Request)
2. 정적 / 동적 컨텐츠 분기 처리
3. 스레드 할당 및 서블릿 객체 확인
4. service() 호출 및 doGet() / doPost() 분기
5. 비즈니스 로직 및 DB 연동
6. 응답 생성 및 반환 (HTTP Response)


mvc 패턴 spring에서 실습한 내용. (view는 아파치톰캣에서 자동으로 할당해주기 때문에 제거. )
주요 어노테이션 정리.

1. @SpringBootApplication  / Spring 실행할 때 spring에 필요한 기본세팅( 1.내장톰캣지원 2. 서블릿자동등록 )

2. @RestController /  Spring 에서는 서블릿을 상속이 아닌 @Controller 어노테이션으로 지원( HTTP ) 
   + RestController ( HTTP content-tpye 자동으로 application/json 세팅 )

3. @PostMapping( "/board/save" ) /  만약에 HTTP 요청이 POST 이면 해당 메소드로 연결 + URL (중복없이) 만들기
4.  @GetMapping( "/board/findall" ) / 만약에 HTTP 요청이 GET 이면 해당 메소드로 연결 + URL (중복없이) 만들기
5. @PutMapping( "/board/update" ) /  만약에 HTTP 요청이 PUT 이면 해당 메소드로 연결 + URL (중복없이) 만들기
6. @DeleteMapping( "/board/delete" ) /  만약에 HTTP 요청이 DELETE 이면 해당 메소드로 연결 + URL (중복없이) 만들기

해당 HTTP 테스트는 Talend API 에서 진행! (각 회사마다 다름. )
